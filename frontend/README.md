# VESPER frontend

React, TypeScript and Vite, with Tailwind CSS and shadcn/ui. Bun is the package manager.

## Run it

```bash
bun install
bun dev          # development server
bun run build    # type check + production build
bun run lint     # Oxlint
```

Update Bun to a recent version (`bun upgrade`) before `bun install`. An old Bun
(for example 1.3.12 on Linux) rewrites `bun.lock` to an older format. Never commit
a `bun.lock` change you did not mean to make.

## Structural Relationships: current artifacts

The existing `exposure/` panels now load `GET /api/c-graph/cves/{cve_id}` through
`api/queue.ts` and `exposure/data.ts`. Both the dedicated CVE lookup page and CVE
detail use the same typed loader. The C request is independent of the NVD facts
request, so a missing NVD parquet does not hide available C evidence. Errors never
fall back to fixtures. `sampleStructuralDetails.ts` remains only for tests.

Provider raw PageRank, primary PageRank percentile and complete-case comparison
percentile remain separate. Degree comes only from the saved analysis's raw
`degree` column, never normalized centrality or a browser calculation. Missing
scores/evidence stay null with explicit statuses/reasons; genuine zero is valid.
The graph previews four products and four weaknesses with full evidence in
expandable lists. It is not an attack graph or a deployment inventory.

Configure the backend with these environment variables (absolute paths or paths
relative to the project root; never browser-accessible CSVs):

| Variable | Default / behavior |
|---|---|
| `VESPER_C_FEATURE_PROVIDER_CSV` | `outputs/c_graph_feature_provider_2026-10-17_run2/c_graph_feature_provider.csv` |
| `VESPER_C_SCORES_CSV` | `outputs/c_graph_structural_scalar_disagreement_2026-10-17_run1/c_graph_scores.csv` |
| `VESPER_C_DISAGREEMENT_CSV` | Optional; unset/blank disables Degree and comparison |

The API needs these four files (all under the gitignored `outputs/`, so they are
not in a fresh checkout; copy them from the Component C owner or regenerate):

| File | Generated by |
|---|---|
| `c_graph_feature_provider.csv` + `c_graph_feature_provider.metadata.json` | `scripts/export_c_graph_feature_provider.py` (see `docs/COMPONENT_C_FEATURE_PROVIDER.md`) |
| `c_graph_scores.csv` + `c_graph_scores.csv.metadata.json` | `uv run --offline --no-sync python scripts/export_c_graph_percentile_adapter.py` (see `docs/COMPONENT_C_STRUCTURAL_DISAGREEMENT.md`) |
| disagreement analysis CSV (optional, enables Degree and comparison) | `scripts/analyze_c_graph_structural_disagreement.py` |

If any required file or sidecar is missing, `GET /api/c-graph/cves/{cve_id}`
returns `503` with a "Component C artifacts unavailable" message (no traceback).
Copy `.env.example` entries into `.env` to point at other locations.

Provider metadata must be beside the CSV as `c_graph_feature_provider.metadata.json`;
adapter metadata must be `c_graph_scores.csv.metadata.json`. Both are required.
The service validates their SHA-256 checksums, current model/schema identity,
provider linkage, common snapshot/reference identity, row/status populations and
unique CVE keys before publishing an index. Optional analysis rows must have the
same CVE population and snapshot identity. Requested records additionally verify
raw PageRank and signed comparison consistency. Corrupt inputs fail closed.

Observed on the configured 333,178-CVE artifacts: cold indexing took about 65 seconds,
warm lookups took 9-25 ms, the index occupied about 766 MiB, and the sampled server
peak working set was about 116 MiB. Warm one known-CVE endpoint before a demo.
These observations are machine-specific, not service guarantees.

The first request streams the configured files into a process-private SQLite
index in the operating-system temporary directory. Only analysis fields used by
this UI are retained; outcome annotations are excluded. Subsequent lookups use
indexed keys and do not reparse CSVs. File path/size/mtime changes rebuild the
index under a lock; restart after immutable artifact deployment is recommended.
The old index is not served if configuration becomes invalid. A restart creates
a fresh disposable index, so each worker has cold-start and temporary-disk cost.
No source artifact is written or graph/percentile recomputed. Relationship JSON
fields up to 16 MiB are supported. Warm requests read only one CVE's records.

Responses use snake_case with separate `structural_score`, `raw_pagerank`,
`degree`, `pagerank_comparison_percentile`, `cvss_percentile` and
`pagerank_cvss_disagreement`. Evidence statuses/reasons are separate per layer;
score and comparison populations and artifact hashes are included. No configured
absolute filesystem paths are returned. `404` means outside the C population,
`503` missing configuration/files and `422` invalid identifiers/artifacts/records.
A known abstained/not-eligible CVE returns `200` with null numeric scores.

The C panel may use a different snapshot from the D ranking. Its source is not
silently substituted into `candidate.score_c`; D fusion/planning are unchanged.
The ranking API does not expose `model_version_c`, so its column is cautiously
labeled Structural signal. Verify ranking lineage separately before asserting
that its value is identical to a newly configured C snapshot.

## Data flow

```
D ranking API -> api/queue.ts -> Home / Priority Queue / Sprint plan
C artifact API -> api/queue.ts -> exposure/data.ts -> Structural Relationships / CVE detail
B static model export -> timing/data.ts -> Exploit timing
Legacy sampleQueue -> getQueue/useQueue (not the active ranking data source)
```

- `src/queue/types.ts` mirrors the shared score contracts; API response types live in `src/api/queue.ts`. Keep them in sync.
- The Priority queue page loads the current Component D ranking from
  `GET /api/d-fusion/ranking` and displays its top 25 rows. Its CSV button downloads
  the full ranking from `GET /api/d-fusion/ranking.csv`. The separate `getQueue()`
  helper still returns sample data for pages that use the older queue contract.
- The active ranking and C detail clients are already API-backed; changing the legacy
  `getQueue()` helper is not needed for this integration.

### Sprint plan optimiser

The Sprint plan page is implemented in `src/plan/SprintPlanPage.tsx`. It loads the
backend ranking and submits team capacity, plan period, and start date through
`src/api/queue.ts`. It shows a paginated risk ranking with a full CSV download,
then displays the scheduled and deferred results returned by FastAPI. The
planner endpoints are:

- `GET /api/d-fusion/ranking` loads the configured ranking.
- `GET /api/d-fusion/ranking.csv` downloads that exact ranking.
- Selecting a CVE in the Priority queue loads its local NVD record from
  `GET /api/d-fusion/cves/{cve_id}`. The endpoint reads
  `data/processed/vulnerabilities.parquet`; if that local NVD dataset is absent,
  the UI reports that details are unavailable instead of substituting sample data.
- `POST /api/d-fusion/knapsack` accepts `{ patchers, hours_per_patcher,
  planning_period, start_date, overrides }` and returns scheduled/deferred
  rows, dates, and daily capacity summaries.

Daily plans cover one workday; weekly plans cover five Monday-Friday workdays;
monthly plans cover 22 Monday-Friday workdays. The backend reruns the daily
knapsack for each workday using remaining candidates. The UI downloads the
complete returned plan as a CSV. This multi-day sequence is greedy across days,
and does not model holidays, dependencies, or patcher skill differences.

## Component D patch planner

The VESPER screen includes the current ranking and daily/weekly/monthly patch
planner under `src/plan/SprintPlanPage.tsx`. Start
the API and frontend in separate terminals from the repository root:

```powershell
uv sync --group dev
uv run uvicorn vesper.api.main:app --reload
```

```powershell
cd frontend
bun install
bun run dev
```

The frontend proxies `/api` requests to the local FastAPI service on port 8000.
FastAPI loads `outputs/d_fusion/current_provisional/ranked_current_five_signal.csv`
by default and serves it to React; users do not select or upload the ranking
file. Generate the current fused dataset and ranking first with
`uv run python -m vesper.components.d_fusion.provisional_pipeline`. The backend
can use another CSV when `VESPER_RANKING_CSV` points to it. The UI shows the
full paginated ranking and can download it as CSV. Patch effort defaults to a
labeled CVSS severity-tier estimate; rows without CVSS remain unscheduled until
an effort estimate is supplied. The backend maximizes
`risk_score × business_criticality` under each day's person-hour limit.
Business criticality defaults to 1 unless an override is provided.

Ranking input must contain unique `cve_id` values and a score column named
`risk_score` or `fusion_score` with values from 0 to 1. Optional signal scores,
statuses, provenance dates, `patch_hours`, and `business_criticality` fields
are displayed or loaded when present. The current provisional ranking uses
within-cohort percentile ranks and is explicitly not a trained or validated
model. The backend does not persist overrides between browser sessions.

## Component D patch planner

The VESPER screen includes a daily patch planner under `src/knapsack/`. Start
the API and frontend in separate terminals from the repository root:

```powershell
uv sync --group dev
uv run uvicorn vesper.api.main:app --reload
```

```powershell
cd frontend
bun install
bun run dev
```

The frontend proxies `/api` requests to the local FastAPI service on port 8000.
FastAPI loads `outputs/d_fusion/ranked_vulnerabilities.csv` on the backend and
serves it to React; users do not select or upload the ranking file. Generate it
first with `uv run python -m vesper.components.d_fusion.ensemble rank` if it is
missing. The backend can use a different CSV when `VESPER_RANKING_CSV` points to
it. In the UI, set patchers and daily hours, then add patch-hour estimates and
business criticality (1 low, 2 medium, 3 high) in **All candidates & inputs**.
React sends only capacity and those per-CVE overrides to
`POST /api/d-fusion/knapsack`; FastAPI reloads the backend ranking, validates
the request, and returns separate `scheduled` and `deferred` lists. CVEs
without an effort estimate remain unscheduled. The backend selects the set
that maximizes `risk_score × business_criticality` under the daily person-hour
limit. The main view shows up to the 25 selected CVEs; **Export full CSV**
downloads the complete scheduled and deferred plan.

Ranking input must contain unique `cve_id` values and a score column named
`risk_score` or `fusion_score` with values from 0 to 1. Optional
`patch_hours` and `business_criticality` columns are loaded when present. If
these fields are absent, enter the values in the UI. The backend does not
persist overrides between browser sessions.

## Adding UI components

Only through the shadcn/ui tool. It writes the component into `src/components/ui/`:

```bash
bunx shadcn@latest add input
```

Do not edit generated files or copy components in by hand.

## Rules

- Never show "Component A/B/C/D" in the UI. Use plain names: Text signal, Exploit timing, Structural Relationships, Fusion.
- No other UI libraries (only shadcn/ui, Tailwind and lucide icons).
- Small pull requests, one topic each.
- Sample data must always be labelled as sample data on screen.
- Import from `src` with the `@/` alias, for example `@/components/ui/button`.
